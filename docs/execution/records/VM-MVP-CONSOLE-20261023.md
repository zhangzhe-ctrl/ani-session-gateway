## Behavior

`Target.vm_binding=5` uses Resource's pure `vm.console.v1.VMConsoleBinding` protocol. The session, fingerprint and Memory/Redis storage preserve all ten frozen identity fields. VM and Instance bindings are exclusive; managed VM bindings are restricted to VNC and the verified exact Governance mTLS peer. The existing Instance terminal validation path remains.

The production VNC adapter validates namespace UID, VM UID, exact VM/VMI kinds, VMI UID and controller ownership before opening KubeVirt `vnc`, then repeats native identity and Resource business-closing/version validation after upgrade and before any browser payload can be forwarded. It uses the frozen namespace rather than deriving a replacement target. Configured managed VNC has no name-only fallback. IP, Agent and OS installation state are not admission requirements. Changed targets close the provider stream and the browser connection with the bounded `target_changed` outcome.

`GetSessionReplay` requires the verified Governance peer and performs a pure existing-key read. Tenant, subject, VM ID and original expected version must match; it returns only the original unclaimed, unexpired ticket. It neither calls `CreateOrGet` nor validates/resolves/rebinds the target. Missing, changed and consumed intents retain separate NotFound, AlreadyExists and FailedPrecondition results, allowing Governance's pending-DELETE fence to reject new intents safely.
